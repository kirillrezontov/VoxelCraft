# VoxelCraft 0.8.2-rc1 — UI/UX and Developer Console

A release candidate for the existing C++23 SDL3/Vulkan sandbox. Windows remains
the primary target; actual Windows compilation/gameplay is unverified locally.
This is not a stable release declaration.

## Player-facing changes

- Embedded licensed DejaVu Sans and Mono replace the bitmap default. UTF-8,
  Latin/Cyrillic, scalable metrics, clipping and bounded glyph caching work without
  installing fonts or font development libraries.
- A shared theme gives HUD, inventory, crafting, settings, pause, notifications,
  tooltips and console consistent typography, spacing and restrained selection.
  UI scale persists at 75–175%; layouts constrain to small/high-DPI viewports.
- Creative inventory reads every ItemRegistry entry, including wooden/stone
  pickaxes, ordinary items and mod content. Search names/identifiers, select
  categories and assign non-consuming hotbar items. Original tool/material/food
  icons and a missing-resource fallback share the existing texture atlas.
- Survival drag/merge/swap, rounded-up half-stack transfers and Shift quick transfer
  use the same authoritative inventory transactions. Counts and durability remain
  intact. Crafting shows icons, required/available amounts and disabled actions
  using a read-only eligibility check.
- `/`, T and grave open command/chat overlays with SDL text input, Unicode editing,
  selection/clipboard, bounded history, scrollable output, suggestions, result
  severity and permission-filtered completion. Gameplay input is isolated while
  typing. Escape restores the prior UI/capture state.
- Solo Pause/Settings freeze simulation; multiplayer menus leave the server running.

## Commands and hosting

The same registry handles local, multiplayer and dedicated stdin execution:
`help`, `gamemode`, `give`, `tp`/`teleport`, `summon`, `time`, `seed`, `position`,
`list`, `save`, `spawnpoint`, `say`, `kick`, `op`, `deop`. All required operations
change or query real game services. See [syntax, permissions and examples](v0.8.2-commands.md).

Game modes persist per player and preserve counted inventory. Teleports validate
finite coordinates/world bounds/collision and synchronize a pose revision.
Summons use the existing actor definitions and count limits. Time changes the real
day/night simulation. Saves queue consistent owned snapshots on the existing worker.

Operators require configured authenticated profile identities. `--admin NAME`
bootstraps a role; headless `op`/`deop` persist roles atomically. Anonymous profile
names never inherit stored grants. Network requests have bounded UTF-8 text,
strictly increasing IDs, rate limits and structured replies. Audit logs redact
arguments. Stdin polling does not block simulation or create world-mutating reader
threads; EOF and `--no-console` support services. Signal shutdown retains safe saves.

## Compatibility and scope

World metadata/regions stay format 1. Player payload 10 reads versions 1..9,
retains item identifiers and adds profile mode/spawn fields. Existing creative
assignments resolve item names; missing content remains retained. Mod API 1 gains
optional display metadata without requiring edits to existing packs. Settings 1
migrate to 2 at 100% UI scale. Back up saves before downgrading to old executables.

**Network protocol 4 requires matching 0.8.2 clients and servers**; old protocol 3
is explicitly rejected. UI metadata participates in the content fingerprint.
Private credentials remain plain TCP over a trusted network/tunnel, without a
public account/encryption service.

Weather and full Lua command registration are optional and deferred. Complex
script shaping/localization, user font replacement, remappable bindings, public
account hosting and unrelated new gameplay are outside this milestone. Tiny windows
shrink controls; larger windows are recommended for comfortable reading.

## Validation and remaining platform limits

See [the maintained implementation and acceptance record](v0.8.2-implementation.md)
for baseline/final counts, compiler/sanitizer, multiplayer, Vulkan and extracted
archive evidence. The Windows/MSVC workflow and UTF-8/native console paths are
maintained, but no local Windows run or human cross-platform LAN acceptance is
claimed. Existing broader engine limitations remain in the project roadmap.
