# v0.8.2 command reference

Open `/` for commands, `T` for chat or the grave key for expanded output. Enter
submits; Escape restores the previous screen. Up/Down recall history, Tab cycles
live completions. Headless stdin accepts the same commands with or without `/`.
Commands run on the simulation owner, independently of UI and Vulkan.

Arguments support whitespace, single/double quotes and backslash escapes.
Identifiers are namespaced and case sensitive. Player names are ASCII profile
names, matched case insensitively. `@s` selects the authenticated issuing player;
console commands must supply an explicit player. No other selectors are supported.
Coordinates describe feet, accept finite absolute numbers or `~`, `~5`, `~-10`
relative to the issuer (server anchor for console), and respect finite world height,
supported horizontal range and collision. Unloaded destinations are sampled from
retained/generated terrain; streaming follows the authoritative new position.
`^` local coordinates are not supported.

| Command | Permission | Effect / arguments |
| --- | --- | --- |
| `help [command]` (`?`) | Player | Permitted command descriptions, syntax and required role |
| `position` (`pos`) | Player | Issuer feet coordinates, or console anchor |
| `list` | Player | Connected profiles |
| `say <message…>` | Player | Broadcast bounded UTF-8 chat; T quotes/escapes input automatically |
| `save` | Moderator | Queue an owned consistent snapshot on the save worker |
| `gamemode <survival|creative> [player]` (`gm`) | Administrator | Change mode and movement; keep counted inventory/durability |
| `give <player|@s> <item> [count]` | Administrator | Grant registered block/tool/ordinary/mod item; default 1, max 4096 |
| `tp <x y z>` (`teleport`) | Administrator | Teleport issuer safely |
| `tp <player> <x y z>` | Administrator | Teleport named connected player |
| `tp <player> <targetPlayer>` | Administrator | Teleport player to another player's feet |
| `summon <entity> [x y z]` | Administrator | Spawn registered creature, default issuer feet, max 32 creatures |
| `time query` | Administrator | Real simulation ticks and world clock |
| `time set <day|night|ticks>` | Administrator | Set actual day cycle: 6000/18000 or ticks modulo 24000 |
| `seed` | Administrator | Saved world seed |
| `spawnpoint [player] [x y z]` | Administrator | Persist safe feet destination; default issuer/current position |
| `kick <player> [reason…]` | Moderator | Disconnect a connected player of lower privilege; profile retained |
| `op <player>` | Server console | Persist Administrator for a configured authenticated profile |
| `deop <player>` | Server console | Remove its persisted role |

Examples:

```text
/give @s voxelcraft:stone 64
/give Alice voxelcraft:wooden_pickaxe
/gamemode creative
/tp Alice ~10 ~2 ~-5
/tp Alice Bob
/summon voxelcraft:hostile 10 75 10
/spawnpoint Alice 12.5 65 -8.5
/time set night
/help give
```

Creature definitions are `voxelcraft:grazer` and `voxelcraft:stalker`, with aliases
`voxelcraft:herbivore` and `voxelcraft:hostile`. These are the existing simulation
actors, including ordinary AI, limits, persistence and network replication.
`time` changes the real 20-minute cycle, affecting light and nocturnal AI.
Weather is intentionally optional and absent: no weather simulation exists.

Give is all-or-nothing: insufficient capacity changes nothing. Stack limits and
tool durability come from ItemRegistry. In creative it also assigns the item to
the selected creative hotbar; counted items remain available after changing to
survival. Creative placement never consumes counts. Game mode and custom respawn
locations persist per profile; previous saves inherit the world's mode until set.
Unsafe custom respawn points fall back to ordinary safe spawn search.

## Private server permissions

Single-player owner `Player` has Administrator. Multiplayer clients start at
Player. Credentials use the existing per-profile token authentication; clients
never transmit their desired role or issuer identity in a command request.

```sh
voxelcraft-server --world-dir worlds/friends --auth-file private-identities.txt --admin Alice
voxelcraft --connect 127.0.0.1 --name Alice --identity-file alice.token
```

The auth-file and identity-file formats are documented in [multiplayer.md](multiplayer.md).
`--admin NAME` is a bootstrap grant for a **configured credential**, persisted to
`<world>/operators.vcp`; `--permissions-file PATH` overrides the path. For a temporary
server roles are session-only unless given a permissions file. Remove a bootstrap
flag before using `deop` if revocation should survive subsequent startups. Console
`op Bob` works for configured authenticated profiles even when offline. Anonymous
trusted-LAN names never receive stored roles, even if the same display name has an
operator record. Role files are bounded, checksummed and atomically replaced;
corruption fails startup explicitly. Profile key/token identity semantics are unchanged.

This is private-server authentication over the existing plain TCP transport. Use a
trusted private network/tunnel; it is not public Internet account security. The
server console alone can grant/revoke permissions. Moderators can be provisioned
through the C++ PermissionStore API; no client can escalate to server-console role.

Commands are limited to 1024 UTF-8 bytes and 16 arguments. Output is bounded to
16 lines of 240 bytes. Requests carry increasing IDs; duplicates/oversized wire
requests disconnect the sender. Execution has an eight-command burst and four
commands/second refill, plus existing transport bounds. Flood rejection does not
mutate state. Explicit protocol 4 rejects protocol-3 clients at handshake. Audit
logs include canonical operation, issuer and outcome, without command arguments
or credentials. In-memory client history is not persisted.

Errors distinguish unknown commands, missing/invalid arguments, invalid targets,
permission denied, unavailable context and internal failure. `/save` reports queued
work; the later notification confirms completion or failure. Temporary/busy worlds
report unavailable. Server stdin is polled without a blocking reader thread;
EOF/no stdin leaves simulation alive. SIGINT/SIGTERM retain save-and-stop behavior.
`--no-console` disables stdin command processing for service deployments.

The C++ Registry takes metadata and callbacks and supports additional definitions
without editing the parser. Full Lua command registration is optional/deferred;
Lua's existing restricted gameplay API and mod API 1 remain compatible.
