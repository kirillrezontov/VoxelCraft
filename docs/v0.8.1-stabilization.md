## Architecture and audit evidence

- `vc_server_host`/`voxelcraft-server` link CPU world/gameplay/content/network/storage
  only; SDL/Vulkan discovery is conditional on `VC_BUILD_CLIENT`. Both compiler
  configurations stage shaders beside the client using SDL executable-relative lookup.
  Fetched SDL, GLM, EnTT, JSON, Lua and stb remain pinned; no dependency upgrade.
- Renderer uses one submitted frame fence, one shared depth attachment, coherent
  mapped buffers and presentation semaphores indexed by acquired image. Resource
  wrappers clean partial initialization; renderer shutdown waits before destruction.
  Ordinary mesh/HUD/model replacement now waits on the frame fence, while swapchain
  recreation/shutdown still wait for the device/presentation. Minimized drawing idles.
- Terrain worker capacity 8, mesh capacity 1..4 and snapshot capacity one include
  ready work. Owned neighbor/lighting snapshots and monotonic tickets reject stale
  edits, neighbor/light invalidation, evictions and reinsertion. World/gameplay/GPU
  mutation stays on owner threads. Existing streaming/worker regression coverage
  already tested these guarantees; implementations were retained.
- Existing server input carries intent, never positions/quantities. Reach derives
  from authoritative pose/raycast. Transactional inventory/crafting/mining prevents
  resource duplication/loss; survival state is private per recipient. Rates remain
  120 commands/s with a 240 burst; 4 MiB frames, 8 MiB buffering, 256 queued frames,
  16 pending connections, eight players, 32 saved profiles. Malformed EOF cleanup
  was the confirmed transport defect, reproduced and fixed. Client chunk mirrors
  additionally cap residency at 2,048 chunks.
- Fixed-step collision, unavailable-terrain behavior, landing/death/respawn, tool
  wear, item caps, AI spawn/despawn and multiplayer loot are covered by existing
  `Player`, `Collision`, `Survival`, `Crafting`, `Mining`, `Creatures`, `ServerSurvival`
  tests. Existing health/recipe semantics and identifiers are unchanged.
- JSON content stages registry/items/recipes atomically; invalid dependencies,
  cycles, duplicate IDs, scripts and PNG paths fail explicitly. Hook errors roll
  back edits/inventory and disable only that script. Lua remains API 1 with a 4 MiB
  allocator and 100,000 VM instruction budget, without filesystem/OS/package/debug
  libraries. C-library CPU time is not a hard wall deadline; trusted packs remain
  the supported model. No sandbox security claim is made.
- Snapshot manifest/region version 1, player payloads 1..9 and generators 1..3 are
  unchanged. Existing tests retain unknown block/item/mod identities, old payload
  migration, negative/large coordinates, bounds, inventories, poses and checksums.
  A new recovery test verifies manually quarantining a corrupt newest revision
  exposes the intact preceding revision. Automatic silent rollback is avoided.
- Full palette storage was evaluated but deferred: a 32³ chunk has 65,536 bytes of
  ID payload; retained uniform chunks use a 4-byte RLE run, worst-case retained data
  falls back to 65,536 raw bytes. Save palettes/RLE are already compact. Registry
  and raw chunk APIs remain compatible. Geometry uses 84-byte vertices versus the
  former 68 bytes; optional atlas bounds cost 16 bytes but far fewer vertices are
  emitted for the measured scene. Greedy masks are bounded to 192 visible slices
  of 1,024 cells and only allocated for slices with visible opaque faces.

## Performance measurements

Actual runs on AMD Radeon Graphics (RADV RENOIR), GCC 16.2.1, Linux. CPU benchmark
uses seed 42, generator 3, radius 2, 150 chunks; generation and lighting occur
before timing. Results are single-run measurements, not a universal FPS promise.

| Release paired mode | Vertices | Triangles | Meshing CPU total | Per-chunk median / p95 / max |
| --- | ---: | ---: | ---: | --- |
| Culled unit-face reference | 639,600 | 319,800 | 89.060 ms | 0.060 / 2.540 / 3.784 ms |
| Greedy opaque | 185,836 | 92,918 | 72.150 ms | 0.059 / 1.782 / 2.566 ms |

Synchronous greedy budget-two rebuilds: main-thread p95 3.056 ms, max 3.603 ms,
71.746 ms total. Owned background scheduling: main-thread p95 0.172 ms,
max 0.304 ms, 8.927 ms total; wall 101.743 ms including 1 ms polling sleeps.
The reference path is retained for reproducible paired comparison.

The first greedy attempt scanned each chunk six times and measured 249.871 ms
versus 131.065 ms for reference in that run. It was replaced with one visibility
scan plus masks for visible slices; that slower implementation is not shipped.
Before changes, Debug synchronous/background scheduling produced identical
639,600 vertices; synchronous p95/max 30.522/39.480 ms versus scheduling
0.243/0.674 ms. Debug timings are not compared to Release as speedup claims.
A full solid cube's surface decreases from 6,144 quads to six tiled quads.
No GPU timestamp benchmark or broad FPS improvement is claimed.

## Security and compatibility

Per-profile random tokens are read from bounded local files and checked before
profile selection/creation. Tokens never enter logs, Welcome/profile packets,
worlds or mod state. Credential ownership persists externally across world
restarts; operator rotation revokes access on restart. Existing world profiles
are preserved. Protocol version increases from 2 to 3; clients and servers must
upgrade together. Old versions receive an explicit mismatch, not reinterpretation.

Plain TCP has no encryption/server authentication; network observers or rogue
endpoints can steal credentials. Supported deployment is trusted LAN or a secured
private tunnel. Default unauthenticated loopback is for local development. External
unauthenticated binds require explicit `--trusted-lan`; name impersonation remains
possible in that explicitly trusted mode. Full accounts/TLS/public hosting remain
out of scope. Tests use only isolated temporary worlds and deterministic test tokens.

passed with **eight authenticated clients, 3,900 ticks, 31,180 input commands,
