## Compatibility decisions

Keep metadata/region format 1 and content names unchanged. Add explicitly versioned
player data for per-profile mode/spawn, retaining versions 1..9. Bump the network
protocol explicitly. Creative hotbar assignments remain non-consuming, namespaced
item references; counted backpack/tool durability continue using SurvivalInventory.
Permission grants bind authenticated profile keys; unauthenticated connections
cannot acquire persistent admin roles. Commands and world mutations run on the
simulation owner, never a console reader thread or UI rendering code.

## Compatibility details

Player payload 10 reads all supported 1..9 layouts, including the independent v9
fixture. Profile mode is explicit only after a mode change/save; legacy unset mode
inherits the world default. World metadata/regions remain 1; mod API remains 1;
settings 1 load at scale 1 and save as 2. Creative names resolve ItemRegistry;
missing ordinary items remain placeholders, rather than becoming invented blocks.
A downgrade to old executables cannot read payload 10; preserve backups.

Roles bind existing case-insensitive profile keys and require configured token
authentication. Removing credentials disables privileges even for a stored operator
name. Console alone changes grants. Plain TCP remains private-network transport,
not a public account system. Protocol 3 peers are explicitly rejected by protocol 4.

  registration are deliberately optional; see above. Tiny windows shrink controls.
- Keep this a release candidate until Windows and sustained human cross-platform
  playtesting complete. No known critical crash or data-loss regression remains.
